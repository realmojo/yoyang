# yoyang.keywordegg.com

시군구별 장기요양기관 평가 결과를 보여주는 정보 사이트.
keywordegg 와 같은 스택(Next.js + Supabase + Cloudflare Workers)과 같은 UI 스킨을 쓴다.

기획 배경과 데이터 검증 내역은 [`new-t.MD`](./new-t.MD) 에 있다.

---

## URL 구조

경로가 한 단계다. `app/[slug]/page.tsx` 하나가 네 종류의 화면을 나눠 맡는다.

| 경로 | 화면 | 정의 위치 |
|---|---|---|
| `/` | 홈 | `app/page.tsx` |
| `/지역` | 시도·시군구 허브 | `REGION_HUB_SLUG` (`lib/regions.ts`) |
| `/서울-강남구` | 지역 상세 | `REGIONS` (`data/regions.json`) |
| `/등급` `/비용` `/시설` `/재가` | 가이드 카테고리 | `CATEGORIES` (`lib/contents.ts`) |
| `/장기요양등급-신청방법` | 가이드 글 | `yoyang_contents.slug` |
| `/about` `/contact` `/privacy` `/terms` | 안내 페이지 | 각 디렉터리 |

슬러그는 한글을 쓴다. **글 슬러그가 지역·카테고리 슬러그와 겹치면 글이 가려진다.**
새 글을 넣기 전에 겹치지 않는지 확인할 것.

#### 실측으로 확인한 것 (2026-08-16, 27,947건 전수)

Swagger: <https://infuser.odcloud.kr/oas/docs?namespace=15104801/v1>

응답 필드는 **20개**다. 기획 문서에 적힌 16개에 더해 2025년 지표 4개가 있다.

| 구분 | 필드 |

| 2021·2023·2024 지표 (5개) | 기관운영 · 환경및안전 · 수급자권리보장 · 급여제공과정 · 급여제공결과 |
| 2025 지표 (4개) | 기관운영(2025) · 수급자존중(2025) · 서비스제공(2025) · 서비스결과(2025) |

- 두 지표 체계는 **배타적**이다. 2025년 행은 구 지표 5개가 전부 null이고 그 반대도 같다.
  → 컬럼을 나누고 `eval_system` 으로 구분한다. **섞어서 평균 내면 안 된다.**
- 평가총점은 양쪽 다 100점 척도라 지역 대표값으로는 함께 평균한다.
  (2021~2024 평균 80.94 / 2025 평균 83.49)
- 평가구분은 2021·2023·2024·2025년 정기평가 4회차. **2022년 회차는 없다.**
- 평가일자는 회차와 다를 수 있다(2021년 회차인데 평가일자가 2022년).
  → 회차는 `eval_round`, 실제 방문일은 `eval_date`.
- 급여종류는 `04.방문요양` 처럼 정렬용 번호가 붙어 온다. 화면에서는 번호를 뗀다.
- 설립주체는 개인 22,684 / 법인 4,803 / 지방자치단체 405 / 기타 55.
- 평가등급이 비어 있는 행은 27,947건 중 1건.

#### 일반구는 시로 합친다

원본이 시 단위와 일반구 단위를 섞어 쓴다 — 화성시 64건 vs 일반구 231건,
천안시 7건 vs 구 280건, 안산시 7건 vs 구 335건. 구 단위로 쪼개면 시 단위 행이
갈 곳을 잃는다. 그래서 `"○○시 △△구"` 를 `"○○시"` 로 접고 원래 구 이름은
`sigungu_detail` 에 남겨 기관 표에 표시한다.

규칙 하나(`rollupSigungu`)로 처리해서 일반구가 새로 생겨도 목록을 고칠 필요가
없다. 화성시가 2025년에 실제로 그랬다(만세·효행·병점·동탄구 신설).

결과: 지역 페이지 **229개**, 버려지는 행 **0건**.

#### 분산 검증 (기획 문서 §8-2)

지역마다 값이 실제로 다른지 — 다르지 않으면 지역 페이지가 존재할 이유가 없다.

| 지표 | 전국 평균 | 표준편차 | 범위 |
|---|---|---|---|
| A등급 비율 | 22.8% | 8.9%p | **2.7% ~ 62.5%** |
| 평균 평가총점 | 81.48 | 2.48 | 71.5 ~ 89.3 |

지역별 기관 수 중앙값 95곳(최소 3, 최대 607). 10곳 미만은 2곳뿐이다.
지역 간 차이가 뚜렷해서 기획을 계속 진행할 근거가 된다.

### 적재

```bash
# 1) Supabase SQL 편집기에서 마이그레이션 실행
#    supabase/migrations/001_create_yoyang_tables.sql

# 2) 공공데이터포털에서 15104801 활용신청 → .env.local 에 키·URL 을 넣는다
#    DATA_GO_KR_SERVICE_KEY=<일반 인증키(Decoding)>
#    YOYANG_EVAL_API_URL=<'오픈 API' 탭의 요청 URL, 파라미터 제외>

# 3) 응답 구조부터 확인한다 (1페이지만 받아 실제 필드 이름을 찍어준다)
npm run probe:eval

# 4) 전체 적재 + 집계 갱신
npm run import:eval

# 확인용
npm run import:eval -- --dry-run     # 적재하지 않고 결과만
npm run import:eval -- --pages 3     # 앞 3페이지만

# API 를 못 쓸 때 (내려받은 CSV 로)
npm run import:eval:csv -- data/raw/파일이름.csv
```

**처음 돌릴 때는 `probe:eval` 부터.** 응답 필드 이름이
`scripts/eval-common.mjs` 의 `FIELD_MAP` 후보와 다르면 그 자리에서 멈추고
실제 키를 전부 찍어준다. 포털 문서와 실제 응답이 다른 경우가 있어서,
추측으로 매핑하지 않고 눈으로 확인한 뒤 넘어가려는 장치다.

적재 과정에서 걸러지는 것 두 가지는 **조용히 넘기지 말 것**.

- `data/regions.json` 에 없는 시군구 → 건너뛰고 마지막에 모아서 보고한다.
  그냥 두면 해당 지역 페이지가 통째로 빈다.
- 영역별 점수 5개가 없는 응답 → `null` 로 채우고 경고만 뜬다.
  2025년분은 지표 체계가 달라서(`new-t.MD` §2) 여기 걸릴 수 있다.
  연도별 컬럼 차이는 `FIELD_MAP` 에서 흡수한다.

`(장기요양기관기호, 급여종류, 평가일자)` 가 중복 방지 키다. 같은 키가 한 배치에
두 번 들어가면 Postgres 가 upsert 를 거부하므로 보내기 전에 정리한다.

## 지켜야 할 원칙

기획 문서에서 그대로 옮겨온 것들이다. 화면을 고칠 때 함께 확인할 것.

- **평가일자를 반드시 노출한다.** 정기평가는 급여종류별 3년 주기라 등급이
  몇 년 전 것일 수 있다. 부모님 모실 시설을 고르는 데 쓰는 정보다.
- **시군구 × 급여종류로 페이지를 쪼개지 않는다.** 급여종류는 한 페이지 안의
  섹션으로 둔다. 쪼개면 1,800페이지대가 되고 구글이 대규모 콘텐츠 남용으로 본다.
- **확인되지 않은 숫자를 본문에 쓰지 않는다.** 비급여 금액, CPC, 월 한도액 모두
  해당한다. 월 한도액은 고시로 매년 바뀌므로 해당 연도 고시로 대조한 뒤에 쓴다.
- **공단 기관찾기 화면을 스크래핑하지 않는다.**
- **데이터가 없는 지역은 색인시키지 않는다.** `generateMetadata` 에서 noindex 를
  붙이고 사이트맵에서도 뺀다. 빈 페이지가 대량 색인되면 애드센스 심사에서 걸린다.

## 개발

```bash
npm install
npm run dev          # http://localhost:3000

npm run lint
npm run build

npx wrangler login   # 처음 한 번
npm run cf:preview   # Cloudflare 로컬 미리보기
npm run cf:deploy    # 배포
```

배포 후 Cloudflare 대시보드에서 커스텀 도메인 `yoyang.keywordegg.com` 을 연결한다.

### 캐시 (트래픽이 붙으면)

지역 페이지는 `force-dynamic` 이라(광고를 매 요청 새로 받기 위한 선택) 요청마다
Supabase 를 세 번 친다. 그래서 화면은 매번 그리되 **DB 조회 결과만**
`unstable_cache` 로 1시간 캐시한다 (`lib/region-data.ts`).

단 Cloudflare 에서는 증분 캐시 저장소를 지정해야 이게 요청 사이에 유지된다.
지금은 지정하지 않은 기본 상태라 **캐시가 사실상 동작하지 않는다.**
붙이는 방법은 `open-next.config.ts` 주석에 적어뒀다 (KV 네임스페이스 생성 →
`wrangler.jsonc` 바인딩 → 주석 해제, 순서를 지킬 것).

평가 데이터는 연 1회만 바뀌므로 적재 직후에는 캐시 시간만큼 예전 값이 보일 수 있다.

### 환경변수

`.env.example` 을 `.env.local` 로 복사해 채운다. Supabase 는 keywordegg 와 같은
프로젝트를 쓰고 테이블 접두사로만 나눈다.

### 애드센스

퍼블리셔는 keywordegg 와 같은 계정(`ca-pub-9130836798889522`)이라 **새로 승인받을
필요가 없다.** 다만 광고 단위(슬롯)는 이 사이트용으로 따로 만들어 `lib/ads.ts` 에
넣는다. 슬롯 ID 가 비어 있으면 광고 자리 자체를 그리지 않는다.

승인 전략: 전체 지역을 한꺼번에 깔지 말고 **시군구 50~80개 + 가이드 몇 편** 상태에서
먼저 신청하고, 승인 후 나머지를 채운다.
